## What was done

Follow-up to the prior `rStandardTree` request (`260825_0811_rStandardTree.md`),
which recommended against a `.claude`/`.human` folder split. Brad asked
the natural next question: should there be a dedicated "human agent"
file (mirroring `.claude/agents/<slug>/<slug>.md`, but for the human
side), or does that just go under `Description.md`?

**Answer: no separate file -- put it under `Description.md`.**

- `.claude/agents/` exists to hold *multiple*, distinctly-scoped Claude
  subagent definitions per project (different tool access, different
  instructions each). There's no equivalent need on the human side --
  every project on this Pi has exactly one human, Brad, and his
  relationship to a project doesn't need per-agent-style structure.
- `Description.md` is already established as *the* human-facing file
  (see `_Requests/_Archive/260824_1712_CreateDescription.md`) and the
  dashboard already reads it as such (`find_description_file()`). Any
  human-side context a project ever needs -- who it's for, ownership,
  who to contact -- fits as a line or two there, not as new
  infrastructure.
- A new file type would also need dashboard code to recognize and
  display it (the way `list_agent_files()` globs `.claude/agents/**/*.md`
  today) -- `.claude/agents/` earns that because it's Claude Code's own
  native subagent format the tooling already has to parse; a bespoke
  "human agent" file wouldn't get that for free and isn't worth adding
  code for.

Added one clarifying line to `_Instructions/ProjectSetup.md`'s
`Description.md` bullet recording this, so the question doesn't need to
be re-asked on a future project.

**Outcome:** answered, no new file/folder added. Doc change only
(`ProjectSetup.md`), no app code touched, no restart needed.
