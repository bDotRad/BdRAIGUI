## What was done

Finished and fixed the in-progress "GitHub as a tab" work that was
already sitting uncommitted in `app/templates/project.html` (tab
markup for `#tabs` / `.tab-btn-overview` / `.tab-btn-github` /
`#tab-panel-overview` / `#tab-panel-github` had been added, but no
`switchTab()` function existed yet, and a leftover
`document.getElementById('github-section')...` line pointed at an id

thrown a JS error and left the GitHub tab button permanently hidden).

1. **Tab wiring completed:**
   - Added `function switchTab(name)`, matching the same
     toggle-`.active`-on-btn-and-panel pattern already used on the
     main dashboard (`app/templates/index.html`'s own `switchTab`).
   - Fixed the stale `github-section` reference in `load()` to instead
     reveal `tab-btn-github` (`style.display = ''`) once
     `data.has_github` comes back true — preserving the original
     intent (only show the GitHub tab for projects that actually have
     a git remote) without switching to it automatically, since the
     page still opens on Overview by default.
   - Grouped Requests/Shelved/Description/Claude agent files under the
     "Overview" tab panel (unchanged content, just re-parented), and
     the git status/commit-and-push/version-history panel under the
     "GitHub" tab panel — this was already done in the uncommitted
     diff and left as-is.

2. **Auto-populating / concatenating commit-message log:** added
   `logGitAction(comment)`, which appends a `Date Time - Comment` line
   to the `#git-commit-message` textarea (concatenating onto whatever
   is already there rather than overwriting, per the request) and
   wired it into every in-app action on this page that edits a file
   living in the *target project's* own repo:
   - `saveRequestEdit()` -> `Edited request "<name>"`
   - `shelveRequest()` -> `Shelved request "<name>"`
   - `unshelveRequest()` -> `Unshelved request "<name>"`
   - `deleteShelvedRequest()` -> `Deleted shelved request "<name>"`
   - `saveDescriptionEdit()` -> `Updated Description.md`

   These are the only actions on this page that write to files tracked
   in the project's git repo (viewing files, editing BdRDev's own
   `agent_files` list, etc. don't touch anything), so "something that
   needs a push" was scoped to exactly those. Existing behavior of
   clearing the textarea after a successful commit & push
   (`git-commit-message`) was left untouched, so the log naturally
   starts fresh after each push.
