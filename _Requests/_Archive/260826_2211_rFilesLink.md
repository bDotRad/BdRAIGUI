## What was done

**Investigated:** `app/templates/index.html`'s `cardHtml(p)` function, which
renders each project tile on the Projects tab. It had a plain
`<span class="name">` for the project name, and a separate
`<a class="btn link" href="/project/${encodeURIComponent(p.name)}">Files</a>`
button in the card footer linking to the project's file-browser page
(`project.html`).

**Change made** (in `app/templates/index.html`):
- Removed the standalone `Files` link from the card footer (`card-foot`
  row now starts with `Archive`).
- Turned the project name itself into the hyperlink: `<span class="name">`
  became `<a class="name" href="/project/${encodeURIComponent(p.name)}">`,
  pointing at the same destination the old `Files` button used.
- Added minimal CSS so the new anchor doesn't pick up default browser
  link styling (blue/underlined) at rest -- `.name` now sets
  `color: inherit; text-decoration: none;` with an `:hover` rule
  (`color: var(--accent); text-decoration: underline;`), matching the
  existing hover convention used by `.req-mini-name` elsewhere in the
  same file.

**Verification:** Flask runs with `debug=False`/no autoreload here, so the
template edit doesn't take effect until the process restarts. Per this
project's own CLAUDE.md (no sudo available to this session;
`systemctl restart` needs Brad by hand, but `kill -9` on the running PID
does trigger systemd's `Restart=on-failure`), restarted the live
dashboard: `kill -9` on PID 180581 -> systemd relaunched it as PID 186071
(`systemctl is-active bdrdev-dashboard` -> `active`). Confirmed via
`curl localhost:8420/` that the served HTML now contains
`<a class="name" href="/project/...">` for the project name and zero
occurrences of `Files</a>`.

**Outcome:** done, deployed, and verified live. No handoff needed -- this
was a small, self-contained markup/CSS change in one template file, not
a new feature or schema work.
